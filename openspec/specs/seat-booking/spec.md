# Spec: Seat Booking

## Purpose
Выбор мест, корзина, резервирование с таймаутом, real-time обновление статусов через WebSocket.

## Requirements

### REQ-BOOKING-001: Real-time Статусы Мест
Система должна обновлять статусы мест в реальном времени.

**Statuses:**
- `AVAILABLE` — свободно
- `RESERVED` — зарезервировано
- `SOLD` — продано
- `BLOCKED` — заблокировано

**Scenarios:**
1. **Подписка на обновление статуса**
   - WHEN пользователь подключается к WebSocket /ws/events/:eventId
   - THEN система отправляет initial state всех мест мероприятия

2. **Push-уведомление об изменении**
   - WHEN статус места меняется (бронирование, покупка, освобождение)
   - THEN система отправляет событие seat_status_updated всем подписчикам
   - AND событие содержит { eventId, seatId, oldStatus, newStatus, timestamp }

3. **Задержка обновления < 1 сек**
   - WHEN статус места меняется
   - THEN все подключённые клиенты получают обновление в течение 1 секунды

### REQ-BOOKING-002: Выбор Мест
Пользователь может выбрать одно или несколько мест.

**Scenarios:**
1. **Получение доступных мест**
   - WHEN пользователь отправляет GET /events/:eventId/available-seats
   - THEN система возвращает все места со статусом AVAILABLE

2. **Выбор мест (добавление в корзину)**
   - WHEN пользователь отправляет POST /cart/ seats с [seatIds]
   - THEN система создаёт запись в корзине
   - AND резервирует места на 10 минут

3. **Проверка доступности при выборе**
   - WHEN пользователь выбирает место, которое уже зарезервировано
   - THEN система возвращает ошибку 'Seat is no longer available'

### REQ-BOOKING-003: Корзина
Система должна управлять корзиной покупателя.

**Scenarios:**
1. **Просмотр корзины**
   - WHEN покупатель отправляет GET /cart
   - THEN система возвращает список зарезервированных мест с таймаутами

2. **Удаление из корзины**
   - WHEN покупатель отправляет DELETE /cart/:reservationId
   - THEN система немедленно освобождает место

3. **Истечение таймаута резерва**
   - WHEN 10 минут прошло с момента резервирования
   - THEN система автоматически освобождает место
   - AND отправляет событие seat_status_updated со статусом AVAILABLE

### REQ-BOOKING-004: Резервирование с Таймаутом
Резервирование должно использовать distributed locks для предотвращения double-selling.

**Scenarios:**
1. **Установка блокировки (Redis)**
   - WHEN пользователь начинает бронирование
   - THEN система устанавливает lock в Redis на 10 минут
   - AND ключ锁: reservation:{eventId}:{seatId}

2. **Отмена блокировки**
   - WHEN заказ оплачен или отменён
   - THEN система снимает блокировку Redis

3. **Возврат блокировки по таймауту**
   - WHEN 10 минут прошло без оплаты
   - THEN Redis автоматически удаляет ключ (TTL)
   - AND место становится AVAILABLE

4. **Конкурирующие бронирования**
   - WHEN два пользователя пытаются забронировать одно место одновременно
   - THEN только один получает lock
   - AND другой получает ошибку 'Seat unavailable'

### REQ-BOOKING-005: Интерактивная Схема Зала
Пользователь должен видеть схему зала с доступными местами.

**Scenarios:**
1. **Получение схемы зала**
   - WHEN пользователь открывает страницу мероприятия
   - THEN система возвращает JSON схему зала с координатами и статусами всех мест

2. **Визуализация статусов**
   - WHEN клиент получает схему зала
   - THEN места отображаются разными цветами по статусу:
     - AVAILABLE — зелёный
     - RESERVED — жёлтый
     - SOLD — серый
     - BLOCKED — красный
