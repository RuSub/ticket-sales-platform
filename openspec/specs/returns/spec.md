# Spec: Returns

## Purpose
Запросы возвратов, подтверждение организатором, освобождение мест.

## Requirements

### REQ-RETURNS-001: Запрос Возврата (BUYER)
Покупатель может запросить возврат билета.

**Scenarios:**
1. **Отправка запроса на возврат**
   - WHEN покупатель отправляет POST /returns с orderId
   - AND заказ имеет статус 'PAID'
   - THEN система создаёт запрос на возврат со статусом 'PENDING'

2. **Ограничение по времени**
   - WHEN событие происходит менее чем через 24 часа
   - THEN система отклоняет запрос на возврат с ошибкой 'Too close to event date'

3. **Отмена запроса на возврат**
   - WHEN покупатель отправляет DELETE /returns/:returnId
   - THEN система удаляет запрос (только со статусом 'PENDING')

### REQ-RETURNS-002: Подтверждение Возврата (ORGANIZER)
Организатор подтверждает или отклоняет возврат.

**Scenarios:**
1. **Получение запросов на возврат (ORGANIZER)**
   - WHEN организатор отправляет GET /organizer/returns
   - THEN система возвращает все запросы на возврат для мероприятий организатора

2. **Подтверждение возврата (ORGANIZER)**
   - WHEN организатор отправляет POST /returns/:returnId/approve
   - THEN система меняет статус на 'APPROVED'
   - AND возвращает деньги (в эмуляции)
   - AND билеты меняют статус на SOLD -> invalid
   - AND места освобождаются (SOLD -> AVAILABLE)

3. **Отклонение возврата (ORGANIZER)**
   - WHEN организатор отправляет POST /returns/:returnId/reject
   - THEN система меняет статус на 'REJECTED'
   - AND билеты остаются валидными
   - AND места остаются SOLD

### REQ-RETURNS-003: Ручные Операции (SUPPORT)
Оператор поддержки может вручную отменять или подтверждать возвраты.

**Scenarios:**
1. **Ручное одобрение (SUPPORT)**
   - WHEN оператор отправляет POST /support/returns/:returnId/approve
   - THEN система выполняет возврат как от организатора

2. **Ручное отклонение (SUPPORT)**
   - WHEN оператор отправляет POST /support/returns/:returnId/reject
   - THEN система отклоняет возврат

### REQ-RETURNS-004: История Возвратов
Система должна вести историю всех возвратов.

**Scenarios:**
1. **Просмотр истории (BUYER)**
   - WHEN покупатель отправляет GET /returns
   - THEN система возвращает все запросы на возврат пользователя

2. **Просмотр истории (ORGANIZER)**
   - WHEN организатор отправляет GET /organizer/returns/history
   - THEN система возвращает полную историю возвратов
