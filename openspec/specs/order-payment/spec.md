# Spec: Order & Payment

## Purpose
Создание заказов, обработка платежей через эмулированный шлюз, генерация QR-билетов.

## Requirements

### REQ-PAYMENT-001: Создание Заказа
Система должна создавать заказ из корзины.

**Scenarios:**
1. **Создание заказа**
   - WHEN покупатель отправляет POST /orders с cartId
   - THEN система создаёт заказ со статусом 'PENDING_PAYMENT'
   - AND резервирует места на 10 минут

2. **Подтверждение резервирования (Saga)**
   - WHEN заказ создан
   - THEN система запускает Saga:
     1. Reserve seats (Redis + DB)
     2. Create order record
     3. Send confirmation event
   - AND при ошибке любого шага — откатить предыдущие

3. **Отмена заказа до оплаты**
   - WHEN покупатель отправляет POST /orders/:id/cancel
   - THEN система меняет статус на 'CANCELLED'
   - AND освобождает все зарезервированные места

### REQ-PAYMENT-002: Эмулированный Платёжный Шлюз
Система должна эмулировать платёжный шлюз с подготовкой к реальному.

**Scenarios:**
1. **Инициация оплаты**
   - WHEN покупатель отправляет POST /payments/:orderId/charge с paymentMethod
   - THEN система эмулирует обработку платежа
   - AND возвращает результат через 1-2 секунды

2. **Успешная оплата**
   - WHEN платёж успешен
   - THEN статус заказа меняется на 'PAID'
   - AND места меняют статус на SOLD

3. **Неуспешная оплата**
   - WHEN платёж отклонён
   - THEN статус заказа меняется на 'PAYMENT_FAILED'
   - AND места возвращаются в AVAILABLE

4. **Идемпотентность платежа**
   - WHEN покупатель отправляет один и тот же запрос оплаты дважды
   - THEN система возвращает результат первой обработки
   - AND не создаёт дублирующую транзакцию

### REQ-PAYMENT-003: Генерация QR-Билетов
Система должна генерировать QR-коды для оплаченных билетов.

**Scenarios:**
1. **Генерация QR-кода**
   - WHEN заказ оплачен
   - THEN система генерирует QR-код с уникальным ticketId
   - AND QR содержит: { ticketId, eventId, seatId, price, createdAt }

2. **Отправка на email**
   - WHEN заказ оплачен
   - THEN система отправляет билет на email покупателя
   - AND attachment содержит PDF с QR-кодом

3. **Билет в личном кабинете**
   - WHEN заказ оплачен
   - THEN билет доступен в /orders/:id/ticket
   - AND отображается QR-код и детали

### REQ-PAYMENT-004: Outbox Pattern
Система должна гарантировать доставку событий платежей.

**Scenarios:**
1. **Запись в outbox**
   - WHEN платёж обработан
   - THEN система записывает событие в таблицу outbox
   - AND асинхронный процессор публикует событие в Kafka

2. **Ретрай при ошибке**
   - WHEN публикация события в Kafka не удалась
   - THEN система повторяет попытку с экспоненциальным backoff
   - AND максимум 5 попыток

### REQ-PAYMENT-005: История Заказов
Пользователь должен видеть историю своих заказов.

**Scenarios:**
1. **Получение истории (BUYER)**
   - WHEN покупатель отправляет GET /orders
   - THEN система возвращает все заказы пользователя с пагинацией
   - AND включает статус, дату, сумму, список билетов

2. **Получение деталей заказа**
   - WHEN покупатель отправляет GET /orders/:id
   - THEN система возвращает полный заказ с билетами и статусом
