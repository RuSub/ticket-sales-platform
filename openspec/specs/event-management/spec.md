# Spec: Event Management

## Purpose
Создание, редактирование, просмотр и модерация мероприятий, управление схемами залов и категориями мест.

## Requirements

### REQ-EVENT-001: CRUD Мероприятий
Система должна поддерживать полное управление мероприятиями.

**Scenarios:**
1. **Создание мероприятия (ORGANIZER)**
   - WHEN организатор отправляет POST /events с данными мероприятия
   - THEN система создаёт мероприятие со статусом 'PENDING'
   - AND возвращает id созданного мероприятия

2. **Редактирование мероприятия (ORGANIZER)**
   - WHEN организатор отправляет PATCH /events/:id
   - AND является владельцем мероприятия
   - THEN система обновляет данные мероприятия

3. **Получение списка мероприятий (BUYER)**
   - WHEN покупатель отправляет GET /events
   - THEN система возвращает пагинированный список мероприятий

4. **Получение мероприятия (BUYER)**
   - WHEN покупатель отправляет GET /events/:id
   - THEN система возвращает полное описание мероприятия

5. **Удаление мероприятия (ORGANIZER)**
   - WHEN организатор отправляет DELETE /events/:id
   - AND является владельцем мероприятия
   - THEN система удаляет мероприятие (если нет активных заказов)

### REQ-EVENT-002: Статусы Мероприятий
Мероприятия должны иметь жизненный цикл статусов.

**Statuses:**
- `DRAFT` — черновик
- `PENDING` — на модерации
- `APPROVED` — опубликовано
- `CANCELLED` — отменено организатором
- `HIDDEN` — скрыто администратором

**Scenarios:**
1. **Создание со статусом PENDING**
   - WHEN создается новое мероприятие
   - THEN статус = 'PENDING'

2. **Одобрение мероприятия (ADMIN)**
   - WHEN администратор отправляет POST /admin/events/:id/approve
   - THEN статус меняется на 'APPROVED'

3. **Отклонение мероприятия (ADMIN)**
   - WHEN администратор отправляет POST /admin/events/:id/reject
   - THEN статус меняется на 'HIDDEN'

### REQ-EVENT-003: Шаблоны Схем Залов
Система должна поддерживать готовые шаблоны схем залов с настраиваемыми зонами.

**Scenarios:**
1. **Получение шаблонов**
   - WHEN организатор отправляет GET /venue-templates
   - THEN система возвращает список доступных шаблонов

2. **Применение шаблона**
   - WHEN организатор создаёт мероприятие с templateId
   - THEN система инициализирует схему зала из шаблона

3. **Кастомизация схемы зала**
   - WHEN организатор отправляет PUT /events/:id/venue-layout
   - THEN система обновляет JSONB-поле схемы зала
   - AND валидирует схему (координаты, зоны, валидность)

### REQ-EVENT-004: Категории Мест и Цены
Каждая зона зала должна иметь категорию с ценой.

**Scenarios:**
1. **Настройка категорий (ORGANIZER)**
   - WHEN организатор настраивает схему зала
   - THEN для каждой зоны задаётся category, price, capacity

2. **Просмотр цен (BUYER)**
   - WHEN покупатель открывает страницу мероприятия
   - THEN видит цены по всем категориям

### REQ-EVENT-005: Модерация Мероприятий
Администратор должен модерировать мероприятия перед публикацией.

**Scenarios:**
1. **Очередь модерации (ADMIN)**
   - WHEN администратор отправляет GET /admin/events/pending
   - THEN система возвращает мероприятия со статусом 'PENDING'

2. **Пакетная модерация (ADMIN)**
   - WHEN администратор отправляет POST /admin/events/bulk-modrate
   - THEN система массово меняет статусы мероприятий

### REQ-EVENT-006: Время Старта Продаж
Организатор может установить время начала продаж.

**Scenarios:**
1. **Установка времени продаж (ORGANIZER)**
   - WHEN организатор устанавливает saleStartTime
   - THEN билеты доступны для покупки только после saleStartTime

2. **Проверка доступности продаж**
   - WHEN покупатель пытается купить билет до saleStartTime
   - THEN система возвращает ошибку 'Sales not started yet'
