# Spec Delta

## ADDED Requirements

### Requirement: Horizontal Scale Readiness

Система SHALL сохранять корректную работу при нескольких экземплярах приложения за балансировщиком.

#### Scenario: WebSocket через несколько инстансов
- **WHEN** клиент подписан на комнату события на одном инстансе, а изменение происходит на другом
- **THEN** клиент получает `seat_status_updated` через Redis-адаптер Socket.IO

#### Scenario: 1000 одновременных соединений
- **WHEN** нагрузочный стенд держит 1000 WebSocket-соединений и параллельные бронирования
- **THEN** ошибок соединения и рассинхронизации статусов мест не возникает
- **AND** результат фиксируется в `docs/load-test.md`

#### Scenario: Stateless-инстанс
- **WHEN** любой инстанс получает запрос
- **THEN** он обрабатывает его без локального состояния сессии
- **AND** перезапуск инстанса не теряет активные резервы (они в Redis/БД)

### Requirement: Production Metrics and Alerting

Система SHALL экспортировать метрики приложения в формате Prometheus и иметь правила алертов.

#### Scenario: Метрики HTTP
- **WHEN** Prometheus скрейпит `/api/metrics`
- **THEN** отдаются гистограммы длительности по маршрутам, счётчики запросов и 5xx, состояние outbox
- **AND** метрики не сбрасываются при перезапуске процесса (хранятся в Prometheus)

#### Scenario: Алерт по p95
- **WHEN** p95 бронирования превышает 500 мс дольше 5 минут
- **THEN** Grafana отправляет уведомление по настроенному каналу

### Requirement: Secure Production Deployment

Система SHALL развёртываться с TLS, секретами вне репозитория и применением миграций в CI.

#### Scenario: Деплой
- **WHEN** CI собирает и выкатывает новую версию
- **THEN** `prisma migrate deploy` выполняется до старта приложения
- **AND** секреты берутся из окружения/vault, а не из репозитория

#### Scenario: TLS
- **WHEN** клиент подключается к production-домену
- **THEN** соединение идёт по TLS 1.2+ и HTTP перенаправляется на HTTPS
